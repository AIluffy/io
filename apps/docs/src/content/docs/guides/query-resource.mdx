`@iostore/query` 提供统一的 Query/Resource 运行时，负责：

- 缓存（`staleTime`）
- 请求去重（同 key 并发只执行一次）
- 失效（`invalidate`）
- 重试（`retry` + `retryDelay`）
- 取消（`AbortSignal`）
- 预取（`prefetch`）

## 先有 QueryClient，再有 Resource

```ts
import { createQueryClient, createResource } from '@iostore/query';

const client = createQueryClient({
  defaultStaleTime: 5_000,
});

const userResource = createResource({
  client,
  key: ['user', 1],
  queryFn: async ({ signal }) => {
    const response = await fetch('/api/user/1', { signal });
    return response.json() as Promise<{ id: number; name: string }>;
  },
});
```

`Resource` 是“可复用查询句柄”，拥有 `fetch / prefetch / invalidate / cancel / subscribe / getState / read`。

## useQuery 和 useResource 怎么选

- `useQuery`：组件内直接声明查询，最省代码。
- `useResource`：你已经在组件外创建好 `resource`，或需要多个组件共享同一 resource 实例。

一句话：`useQuery = createResource + useResource` 的组合封装。

## useResource 的典型场景

### 1) 预取后复用

```ts
await userResource.prefetch();
```

随后多个组件都用 `useResource(userResource)`，不会重复发请求（命中缓存或共享 in-flight）。

### 2) 显式失效

```ts
userResource.invalidate();
```

常见于 mutation 成功后，手动标记旧数据无效并触发下一次拉取。

### 3) 页面切换取消请求

```ts
userResource.cancel();
```

减少无效请求占用，尤其在频繁切换路由/标签页时。

## 各框架对应 API

- React: `useQuery` / `useResource`
- Lynx: `useQuery` / `useResource`
- Vue: `useQuery` / `useResource`
- Solid: `useQuery` / `useResource`
- Svelte: `createQueryStore` / `toQueryStore`

## useResource 注意点

- `resource.key` 要稳定且可序列化。
- `queryFn` 要支持 `AbortSignal`，避免取消无效。
- 对“列表+详情”这类并发视图，优先统一 key 约定，便于批量失效。
