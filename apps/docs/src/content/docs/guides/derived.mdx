派生值是基于 IO 状态计算出的只读结果，依赖变化时自动更新。

## 方式一：显式依赖

```ts
import { derived, io } from '@iostore/store';

const count = io(0);
const doubled = derived([count], (value) => value * 2);
```

当你的状态来自 Tree 时，也可以把“路径 Unit”当作原子依赖传入：

```ts
import { derived, io } from '@iostore/store';

const store = io({ user: { name: 'Ada' }, count: 0 });
const summary = derived(
  [store.user.name, store.count],
  (name, count) => `${name} · ${count}`,
);
```

## 方式二：树选择器

```ts
const store = io({ count: 0, user: { name: 'Ada' } });

const summary = derived(store, (s) => `${s.user.name} · ${s.count}`);
```

## 方式三：自动追踪

```ts
const store = io({ count: 0, rate: 2 });

const total = derived(() => store.count.get() * store.rate.get());
```

## 为什么不做“隐式自动追踪”

`derived()` 提供三种方式，是为了保持依赖语义清晰：

- **显式依赖**：订阅来自传入的依赖对象，最稳定、最可控。
- **树选择器**：订阅来自传入的树节点（不是 selector 内的访问路径）。
- **自动追踪**：依赖来自 `get()` 的运行时读取，适合需要信号式追踪的场景。

如果把它们合并成“隐式自动追踪”，就会让依赖来源变得不透明，
既难以解释订阅范围，也不利于性能与调试。因此 IO 保持显式语义，
并将“自动追踪”限定在 `derived(() => ...)` 这种明确表达上。

## 订阅派生值

```ts
const stop = doubled.subscribe((value) => {
  console.log(value);
});
```

## 场景：依赖多个 store / key 触发函数执行

当你需要“任一依赖变化就执行某个函数”时，可以先组合一个 `derived`，再订阅它：

```ts
import { batch, derived, io } from '@iostore/store';

const user = io({ age: 18, level: 1 });
const order = io({ amount: 99 });

const trigger = derived(
  [user.age, user.level, order.amount],
  (age, level, amount) => ({ age, level, amount }),
);

const run = ({
  age,
  level,
  amount,
}: {
  age: number;
  level: number;
  amount: number;
}) => {
  // 你的业务函数
  console.log('run with', { age, level, amount });
};

// 如果需要初始化立即执行一次
run(trigger.get());

const stop = trigger.subscribe(run);

// 一次事务里改多个依赖时，使用 batch 合并通知，避免重复触发
batch(() => {
  user.age.set(19);
  order.amount.set(199);
});
```

## 注意事项

- 派生值只读，不能 `set`。
- 使用 `get()` 读取时会参与依赖追踪。
- 依赖链过长时建议拆分为多个派生值。
