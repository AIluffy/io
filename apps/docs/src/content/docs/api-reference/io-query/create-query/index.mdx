## 何时使用

当你需要一个无框架依赖、可手动控制生命周期的 Query 实例时使用 `createQuery`。
在应用层通常优先用 `client.query(...)`，由客户端统一处理 key 去重与缓存复用。

## 签名

```ts
function createQuery<TData = unknown, TError = Error>(
  options: IoQueryOptions<TData, TError>,
): IoQuery<TData, TError>;
```

## 参数

| Name | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `options` | `IoQueryOptions<TData, TError>` | Yes | — | 配置 key、请求函数、缓存时序、重试策略与回调。 |

## 返回

`IoQuery<TData, TError>`

返回一个响应式 Query 对象，包含 `fetch`、`fetchQuietly`、`refetch`、`prefetch`、`invalidate`、`cancel`、`setData`、`read`、`getData` 等方法。

## 最小示例

```ts
import { createQuery } from '@iostore/store/query';

const userQuery = createQuery({
  key: ['user', 1],
  queryFn: async ({ signal }) => {
    const res = await fetch('/api/users/1', { signal });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json() as Promise<{ id: number; name: string }>;
  },
  staleTime: 10_000,
  retry: 2,
});

await userQuery.fetch();
await userQuery.refetch();
console.log(userQuery.getData());
```

## 常见误用

- `queryFn` 未透传 `signal`，导致 `cancel()` 无法真正中断网络请求。
- 在渲染路径内构造不稳定 key，导致缓存槽位抖动。
- 在组件里直接到处 `createQuery`，而不是复用 `client.query(...)`。
