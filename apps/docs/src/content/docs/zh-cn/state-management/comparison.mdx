## 选择依据

在 Astro 中通常通过 islands 渲染交互，因此“状态放在哪里、如何 hydration”是关键。选型时建议优先关注：

- 数据流是否清晰可控
- SSR/同构能力与约束
- 订阅粒度与渲染成本
- 团队维护与扩展成本

## 对比矩阵

<StateComparisonTable caption="主流状态管理库对比" hint="可点击表头排序。">

| 库名称        | 数据流模型      | 更新粒度 | SSR 友好度 | 学习曲线 | 适用场景 |
| ------------- | --------------- | -------- | ---------- | -------- | -------- |
| IO（本库）    | 直接写入 + patch | 细       | 高         | 低       | 深层状态、需要回放与精细订阅 |
| Redux         | Action → Reducer | 中       | 高         | 中       | 强规范与可审计流程 |
| Zustand       | 命令式写入       | 中       | 中         | 低       | 轻量状态与快速落地 |
| Pinia         | Store + Action   | 中       | 中         | 中       | Vue 生态内状态管理 |
| Solid Store   | Signals          | 细       | 高         | 中       | 响应式依赖链路复杂 |
| Svelte Store  | Store/订阅       | 中       | 高         | 低       | Svelte 生态或轻量 store |

</StateComparisonTable>
