## 是什么

Nuxt 场景通常用 `useAsyncData` 完成 server 预取，再把结果注入 query client 统一后续缓存策略。

## 何时使用

- 你要在 Nuxt 首屏阶段预取业务数据。
- 你要让客户端后续刷新继续复用 query 规则。

## 核心 API

- [frameworks/nuxt](/frameworks/nuxt/)
- [create-query-client](/api-reference/io-query/create-query-client/)
- [use-query](/api-reference/io-vue/use-query/)

## 最小示例

```ts
const { data } = await useAsyncData('dashboard', () => $fetch('/api/dashboard'));

const client = createQueryClient();
if (data.value) {
  client.setQueryData(['dashboard'], data.value);
}
```

## 常见误区

- 只依赖 `useAsyncData`，不建立后续 query 失效机制。
- payload 与 key 设计不一致，导致客户端不命中。
- 混用多套缓存规则，难以排查数据来源。

## 实践建议

- 明确 SSR 阶段与 CSR 阶段各自的职责。
- 统一 dashboard 类场景的 key 前缀。
- 首屏命中后保留手动刷新与失效能力。
