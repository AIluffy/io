## 是什么

Next.js 适配重点不在 hooks 本身，而在 SSR 边界：按请求创建 client、服务端预取、客户端注入。

## 何时使用

- 你使用 App Router，并希望首屏先命中缓存。
- 你要避免服务端请求之间的缓存串写。

## 核心 API

- [create-query-client](/api-reference/io-query/create-query-client/)
- [use-query](/api-reference/io-react/use-query/)
- [use-suspense-query](/api-reference/io-react/use-suspense-query/)

## 最小示例

```tsx
// server
const client = createQueryClient();
await client.query({
  key: ['dashboard', userId],
  queryFn: ({ signal }) => fetchData(userId, signal),
}).prefetch();

const initialData = client.getQueryData(['dashboard', userId]);

// client
if (initialData) {
  client.setQueryData(['dashboard', userId], initialData);
}
```

## 常见误区

- 在模块顶层定义 singleton client 用于所有请求。
- server 与 client 使用不同 key 结构。
- hydration 注入后忘记保留后续失效刷新逻辑。

## 实践建议

- 把“每请求创建 client”当成硬约束。
- SSR 只传可序列化 plain data。
- 页面写操作后仍走 invalidate 路径。
