## Selection Criteria

In Astro, interactive UI is usually rendered via islands, so “where state lives and how hydration works” is key. Consider:

- Data flow clarity and constraints
- SSR/isomorphic friendliness
- Subscription granularity
- Team maintenance cost

## Comparison Matrix

<StateComparisonTable caption="State library comparison" hint="Click column headers to sort.">

| Library       | Data Flow        | Granularity | SSR Friendly | Learning Curve | Best For |
| ------------- | ---------------- | ----------- | ------------ | -------------- | -------- |
| IO (this lib) | Direct writes + patches | Fine | High | Low | Deep state + replay + precise subscriptions |
| Redux         | Action → Reducer  | Medium | High | Medium | Strong conventions and auditability |
| Zustand       | Imperative writes | Medium | Medium | Low | Lightweight state, quick adoption |
| Pinia         | Store + Action    | Medium | Medium | Medium | Vue ecosystem state management |
| Solid Store   | Signals           | Fine | High | Medium | Complex reactive dependency chains |
| Svelte Store  | Store/subscribe   | Medium | High | Low | Svelte ecosystem or lightweight stores |

</StateComparisonTable>
