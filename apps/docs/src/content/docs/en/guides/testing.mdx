## Prefer snapshot assertions

Snapshots are frozen and stable within a revision, so they are ideal for tests.

```ts
import { expect, it } from 'vitest';
import { io } from 'io-store';

it('updates count', () => {
  const count = io(0);
  count.update((v) => v + 1);
  expect(count.snapshot()).toBe(1);
});
```

## Test a store shape

```ts
import { expect, it } from 'vitest';
import { io } from 'io-store';

it('updates deep fields', () => {
  const store = io({ user: { name: 'Ada' } });
  store.user.name.set('Grace');
  expect(store.snapshot()).toEqual({ user: { name: 'Grace' } });
});
```

## Assert patches

Use `subscribeUpdate` to inspect the exact patches produced by an action.

```ts
it('emits update patches', () => {
  const count = io(0);
  const patches = [] as string[];
  const unsub = count.subscribeUpdate((u) => {
    patches.push(u.patches[0].op);
  });

  count.set(1);
  unsub();

  expect(patches).toEqual(['set']);
});
```

## Tips

- Wrap your mutations in plain functions so you can reuse them in app code and tests.
- Prefer value assertions for behavior and patch assertions for auditing.
