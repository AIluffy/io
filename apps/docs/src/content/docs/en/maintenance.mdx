## Access Control

- The published docs site is a static site. If it is hosted on GitHub Pages, end-user access control is not enforced by the site itself.
- Use repository permissions, branch protection rules, and required reviews to control who can change documentation.
- If you need authenticated access for readers, host the static site behind an access gateway (for example, a reverse proxy with SSO).

## Update Workflow

- Treat `apps/docs/src/content/docs/**` as product code: changes require PR review.
- If a public API changes, regenerate API reference pages:

```bash
npm run docs:generate-api
```

- Verify that the generated docs are committed and in sync:

```bash
npm run docs:check
```

- Build the docs site locally:

```bash
npm run build -w apps/docs
```

## CI Enforcement

- CI runs `docs:check` to prevent API docs from drifting away from source exports.
- Docs deployment runs API generation before building the site, so docs stay up to date when code changes.
