Nuxt SSR follows the same core rules:

- Create store per request, not as a server singleton
- Keep hydration boundary payloads plain and serializable
- Pass values through payload, then recreate store on runtime side

## Per-Request Store

Create the store in page/layout setup flow, not at module top-level:

```vue
<!-- pages/dashboard.vue -->
<script setup lang="ts">
import { provide } from 'vue';
import { io } from '@iostore/store';

type AppState = {
  count: number;
  profile: { id: string; name: string } | null;
};

const { data } = await useAsyncData('dashboard', () =>
  $fetch<{ profile: AppState['profile'] }>('/api/dashboard')
);

const initialState: AppState = {
  count: 0,
  profile: data.value?.profile ?? null,
};

const store = io(initialState);
provide('io-store', store);
</script>
```

This runs per request on server and per app instance on client, so state is isolated.

## Hydration Boundary

In Nuxt, `useAsyncData` / payload transfer is your hydration boundary.

Rules:

- Boundary payload should be JSON-serializable.
- Store instances stay runtime-only and should not be placed into payload.

## Server / Client Value Passing

Recommended flow: `useAsyncData -> initialState(plain) -> io(initialState)`.

```vue
<!-- components/dashboard-panel.vue -->
<script setup lang="ts">
import { inject } from 'vue';
import { ioRef } from '@iostore/vue';
import type { IoScope } from '@iostore/store';

type AppState = {
  count: number;
  profile: { id: string; name: string } | null;
};

const store = inject<IoScope<AppState>>('io-store');
if (!store) throw new Error('io-store is not provided');

const count = ioRef(store.count);
</script>
```

Avoid:

- `const store = io(...)` at module scope on server
- Passing store instances via `useState`
