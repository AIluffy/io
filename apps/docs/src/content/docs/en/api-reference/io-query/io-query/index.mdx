## When to Use

Use `IoQuery` when you need both reactive reads (`get`, `snapshot`, `subscribe`) and imperative query controls.

## Signature

```ts
type IoQuery<TData = unknown, TError = Error> =
  IoUnit<IoQueryState<TData, TError>> & {
    readonly key: IoQueryKey;
    readonly keyHash: string;
    fetch(): Promise<TData>;
    fetchQuietly(): void;
    refetch(): Promise<TData>;
    prefetch(): Promise<void>;
    read(): TData;
    getData(): TData | undefined;
    invalidate(refetch?: boolean): void;
    cancel(): void;
    setData(updater: TData | ((prev: TData | undefined) => TData)): void;
    readonly isActive: boolean;
    readonly observerCount: number;
    readonly flags: IoQueryDerivedFlags;
  };
```

## Properties

| Name | Type | Description |
| --- | --- | --- |
| `key` | `IoQueryKey` | Original query key. |
| `keyHash` | `string` | Deterministic hash used by client cache. |
| `isActive` | `boolean` | `true` when at least one subscriber exists. |
| `observerCount` | `number` | Current active subscriber count. |
| `flags` | `IoQueryDerivedFlags` | Derived boolean state helpers. |

## Methods

| Method | Signature | Description |
| --- | --- | --- |
| `fetch` | `() => Promise<TData>` | Fetches using stale-time semantics. |
| `fetchQuietly` | `() => void` | Fire-and-forget fetch for lifecycle/effect paths. |
| `refetch` | `() => Promise<TData>` | Forces a network request. |
| `prefetch` | `() => Promise<void>` | Fire-and-forget prefetch that resolves `void`. |
| `read` | `() => TData` | Suspense-style read: may throw `Promise`/`Error`. |
| `getData` | `() => TData \| undefined` | Returns current cached data shortcut. |
| `invalidate` | `(refetch?: boolean) => void` | Marks stale and optionally background-refetches. |
| `cancel` | `() => void` | Aborts current in-flight request. |
| `setData` | `(updater) => void` | Writes cache data and marks status as success. |
| `get / snapshot / subscribe / reset` | from `IoUnit` | Base reactive unit operations. |

## Minimal Example

```ts
const query = client.query({
  key: ['todos'],
  queryFn: ({ signal }) => fetch('/api/todos', { signal }).then((r) => r.json()),
});

const unsub = query.subscribe(() => {
  console.log(query.snapshot().status, query.flags.isFetching);
});

query.fetchQuietly();
await query.refetch();
unsub();
```

## Common Pitfalls

- Calling `read()` in imperative code paths where thrown `Promise`/`Error` is not expected.
- Assuming `fetch()` always requests network data; with fresh data it can return cache immediately.
- Forgetting to unsubscribe long-lived listeners.
