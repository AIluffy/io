## When to Use

Pass `IoQueryOptions` to `createQuery` or `client.query` to configure keying, fetching, freshness, GC, retry, and lifecycle callbacks.

## Signature

```ts
type IoQueryOptions<TData = unknown, TError = Error> = {
  key: IoQueryKey;
  queryFn: (context: { signal: AbortSignal }) => Promise<TData>;
  staleTime?: number;
  gcTime?: number;
  retry?: number;
  retryDelay?: (attempt: number) => number;
  autoFetch?: boolean;
  placeholderData?: TData | (() => TData);
  onSuccess?: (data: TData) => void;
  onError?: (error: TError) => void;
  onSettled?: (data: TData | undefined, error: TError | null) => void;
};
```

## Properties

| Name | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `key` | `IoQueryKey` | Yes | — | Cache identity. Must be serializable and stable. |
| `queryFn` | `(context: { signal: AbortSignal }) => Promise<TData>` | Yes | — | Async data loader; always forward `signal`. |
| `staleTime` | `number` | No | `0` | Freshness window in ms. `0` means always stale. |
| `gcTime` | `number` | No | `300000` | GC delay in ms after last observer unsubscribes. |
| `retry` | `number` | No | `0` | Retry attempts on non-abort failures. |
| `retryDelay` | `(attempt: number) => number` | No | `min(1000 * 2^attempt, 30000)` | Delay before next retry. |
| `autoFetch` | `boolean` | No | `false` | Fetch immediately after creation. |
| `placeholderData` | `TData \| (() => TData)` | No | `undefined` | Initial pending-state data placeholder. |
| `onSuccess` | `(data: TData) => void` | No | `undefined` | Called after successful fetch. |
| `onError` | `(error: TError) => void` | No | `undefined` | Called after failed fetch. |
| `onSettled` | `(data: TData \| undefined, error: TError \| null) => void` | No | `undefined` | Called on success and error paths. |

## Minimal Example

```ts
const query = client.query({
  key: ['todos', { status: 'active' }],
  queryFn: ({ signal }) =>
    fetch('/api/todos?status=active', { signal }).then((r) => r.json()),
  staleTime: 5_000,
  gcTime: 10 * 60_000,
  retry: 2,
  autoFetch: true,
});
```

## Common Pitfalls

- Omitting request parameters from `key`, causing cache collisions.
- Not forwarding `signal` in `queryFn`, so cancellation cannot abort network work.
- Assuming default retries are enabled; default is `retry: 0`.
