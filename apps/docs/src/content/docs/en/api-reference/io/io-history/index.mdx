## Behavior Notes

- `undo/redo`: move one recorded update at a time.
- `undoGroup/redoGroup`: move by grouped updates (based on `groupBy`).
- `checkpoint`: forces the next recorded update into a new group.
- `cursor`: current pointer (`-1` means before first history entry).

## Common Pitfalls

- Expecting `undoGroup` batching without configuring `groupBy`.
- Reusing a history instance after calling `destroy`.
