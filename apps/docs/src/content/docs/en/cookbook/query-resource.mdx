`@iostore/query` provides a shared Query/Resource runtime for:

- Cache (`staleTime`)
- In-flight dedupe (same key, one request)
- Invalidation (`invalidate`)
- Retry (`retry` + `retryDelay`)
- Cancellation (`AbortSignal`)
- Prefetch (`prefetch`)

## QueryClient First, Resource Next

```ts
import { createQueryClient, createResource } from '@iostore/query';

const client = createQueryClient({
  defaultStaleTime: 5_000,
});

const userResource = createResource({
  client,
  key: ['user', 1],
  queryFn: async ({ signal }) => {
    const response = await fetch('/api/user/1', { signal });
    return response.json() as Promise<{ id: number; name: string }>;
  },
});
```

A `Resource` is a reusable query handle with `fetch / prefetch / invalidate / cancel / subscribe / getState / read`.

## When to choose useQuery vs useResource

- `useQuery`: declare query directly inside a component.
- `useResource`: reuse an already-created `resource`, or share one resource instance across components.

In short: `useQuery` is `createResource + useResource` wrapped for convenience.

## Typical useResource scenarios

### 1) Prefetch then reuse

```ts
await userResource.prefetch();
```

Then multiple components can call `useResource(userResource)` without duplicate requests.

### 2) Explicit invalidation

```ts
userResource.invalidate();
```

Useful after mutations when old cache is no longer valid.

### 3) Cancel on page transition

```ts
userResource.cancel();
```

Avoids wasting network work when users switch routes/tabs quickly.

## Framework-level APIs

- React: `useQuery` / `useResource`
- Lynx: `useQuery` / `useResource`
- Vue: `useQuery` / `useResource`
- Solid: `useQuery` / `useResource`
- Svelte: `createQueryStore` / `toQueryStore`

## useResource checklist

- Keep `resource.key` stable and serializable.
- Make `queryFn` honor `AbortSignal`.
- Standardize key conventions for list/detail pages to simplify invalidation.
