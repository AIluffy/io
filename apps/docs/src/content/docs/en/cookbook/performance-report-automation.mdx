This page explains how to turn benchmark data into publishable documentation as a continuous trust asset.

## Goals

- Generate an up-to-date performance page on every mainline build.
- Surface trends, regressions, and runtime environment automatically.
- Connect performance status to release gates.

## Existing Entry Points

- Benchmark page: [/en/cookbook/benchmark/](/en/cookbook/benchmark/)
- Details page: access via the internal link on the Benchmark page
- Generation command: `npm exec nx -- run apps-docs:generate-bench`

## Recommended Pipeline

1. CI runs `@iostore/store:bench` and `@iostore/store:bench-gc`
2. Aggregation script updates historical JSON data
3. Benchmark docs pages are generated
4. Docs are built and published

## Release Gate Recommendation

- Define budget thresholds for key scenarios (for example mean regression > X%).
- When threshold is exceeded:
  1. mark report sections in red
  2. emit CI warnings/failures
  3. require explicit release risk acknowledgment

## Minimum Page Fields

- Runtime environment (Node/platform/CPU/time)
- Trend charts for key scenarios (at least 5)
- Delta vs previous run (top regressions/improvements)
- Summary conclusion and risk notes

## Common Pitfalls

- Looking at one run only instead of trends.
- Mixing data from inconsistent machines.
- Not wiring perf signals into release governance.
