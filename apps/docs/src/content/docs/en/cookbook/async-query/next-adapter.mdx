## What It Is

Next integration is primarily an SSR boundary problem: create client per request, prefetch on server, and seed cache on client.

## When to Use

- You use App Router and need faster first render.
- You need strict request isolation for cached query data.

## Core API

- [create-query-client](/en/api-reference/io-query/create-query-client/)
- [use-query](/en/api-reference/io-react/use-query/)
- [use-suspense-query](/en/api-reference/io-react/use-suspense-query/)

## Minimal Example

```tsx
// server
const client = createQueryClient();
await client.query({
  key: ['dashboard', userId],
  queryFn: ({ signal }) => fetchData(userId, signal),
}).prefetch();

const initialData = client.getQueryData(['dashboard', userId]);

// client
if (initialData) {
  client.setQueryData(['dashboard', userId], initialData);
}
```

## Common Pitfalls

- Defining a global singleton client for server requests.
- Divergent key shape between server and client.
- Seeding cache but skipping later invalidation logic.

## Practical Guidance

- Enforce request-scoped client creation.
- Seed only serializable payloads.
- Keep post-hydration invalidation/refetch available.
