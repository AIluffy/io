## Choosing between useQuery and useInfiniteQuery

| Scenario | Recommendation |
| --- | --- |
| Single resource / single page data | `useQuery` |
| Endless list, load more, chat history | `useInfiniteQuery` |

## Minimal useInfiniteQuery example

```tsx
import { useInfiniteQuery } from '@iostore/react';

const feed = useInfiniteQuery({
  key: ['feed'],
  initialPageParam: 0,
  queryFn: ({ signal, pageParam }) =>
    fetch(`/api/feed?cursor=${pageParam}`, { signal }).then((r) => r.json()),
  getNextPageParam: (lastPage) => lastPage.nextCursor,
  cancelOnUnmount: true,
});

const rows = feed.data?.pages.flatMap((page) => page.items) ?? [];
```

## Suspense flows

As with `useSuspenseQuery`, pair `useSuspenseInfiniteQuery` with ErrorBoundary.
Loading is delegated to Suspense fallback instead of manual `isLoading` branches.

## Common pitfalls

- Ignoring `signal` in `queryFn`, breaking cancellation.
- Treating `AbortError` as user-facing business failure.
- Building endless lists with `useQuery` + manual page stitching.
