## What It Is

Pagination workloads need stable page keys, selective prefetch, and cancellation of outdated in-flight requests.

## When to Use

- Data is loaded by page/cursor.
- You want next-page prefetch to smooth UX.
- You need to avoid stale overwrite during fast switches.

## Core API

- [io-query-key](/en/api-reference/io-query/io-query-key/)
- [io-query-filter](/en/api-reference/io-query/io-query-filter/)
- [io-query-client](/en/api-reference/io-query/io-query-client/)

## Minimal Example

```ts
const current = client.defineQuery({
  key: ['users', { page, pageSize }],
  queryFn: ({ signal }) => fetch(`/api/users?page=${page}&pageSize=${pageSize}`, { signal }).then((r) => r.json()),
});

if (current.getData()?.hasMore) {
  const next = page + 1;
  await client
    .query({
      key: ['users', { page: next, pageSize }],
      queryFn: ({ signal }) =>
        fetch(`/api/users?page=${next}&pageSize=${pageSize}`, { signal }).then((r) => r.json()),
    })
    .prefetch();
}

current.cancel();
```


## getData() vs snapshot().data

`current.getData()` is a shortcut for `current.snapshot().data`.
Use whichever reads better in your call site; both reflect current cached data.

## Common Pitfalls

- Missing page/cursor params in key.
- Prefetching on every scroll event without guard.
- Appending rows without id-based dedupe.

## Practical Guidance

- Prefetch only when `hasMore` is true.
- Treat cancellation as control flow, not business failure.
- Standardize pagination response shape across endpoints.
