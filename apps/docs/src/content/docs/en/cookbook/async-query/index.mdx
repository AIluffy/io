## What It Is

This section focuses on `@iostore/store/query` and its adapters, covering lifecycle control, caching strategy, optimistic mutation flow, and SSR seeding.

## When to Use

- You need one model for requests, retries, cancellation, and invalidation.
- You want to reuse query semantics across multiple frameworks.
- You need aligned CSR and SSR cache behavior.

## Learning Path

1. Start with the [Async TodoList Tutorial](./tutorial-async-todo-list/) to get one complete end-to-end flow.
2. Continue in the [Playground](./playground/) to observe failure, retry, and recovery behavior.
3. Move to [Vanilla: Query Client and Lifecycle](./vanilla-query-client-and-lifecycle/) for shared runtime semantics.
4. Add [useIO and Common Capability Composition](./useio-and-common-capabilities/) to connect local UI state and query state.
5. Build core capabilities (keys, cache, mutation, pagination, SSR), then apply them in adapters.
