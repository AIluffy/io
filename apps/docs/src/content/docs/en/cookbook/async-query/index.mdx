## What It Is

This section focuses on `@iostore/store/query` and its adapters, covering lifecycle control, caching strategy, optimistic mutation flow, and SSR seeding.

## When to Use

- You need one model for requests, retries, cancellation, and invalidation.
- You want to reuse query semantics across multiple frameworks.
- You need aligned CSR and SSR cache behavior.

## Learning Path

1. Start in the [Playground](./playground/) to build intuition with a live query flow.
2. Continue with [Vanilla: Query Client and Lifecycle](./vanilla-query-client-and-lifecycle/).
3. Add [useIO and Common Capability Composition](./useio-and-common-capabilities/) to connect local UI state and Query flow.
4. Build core capabilities: keys, cache, mutation, pagination, SSR.
5. Apply the same strategy to framework adapters.
