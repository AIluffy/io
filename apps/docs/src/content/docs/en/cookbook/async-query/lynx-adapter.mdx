## What It Is

The Lynx adapter keeps React-like query ergonomics while preserving cancellation and dedupe behavior for mobile interaction patterns.

## When to Use

- Lynx pages need query/mutation workflows.
- You need robust behavior under weak network and rapid switching.

## Core API

- [use-query](/en/api-reference/io-lynx/use-query/)
- [io-lynx-query-result](/en/api-reference/io-lynx/io-lynx-query-result/)

## Minimal Example

```tsx
import { useQuery } from '@iostore/lynx';

const feed = useQuery({
  key: ['feed', category],
  queryFn: ({ signal }) =>
    fetch(`/api/feed?category=${category}`, { signal }).then((r) => r.json()),
  cancelOnUnmount: true,
});
```

## Common Pitfalls

- Logging cancellation as production failure.
- Missing category/page params in key.
- Excessive retry configuration in weak networks.

## Practical Guidance

- Default to cancel-on-unmount for mobile route switches.
- Classify retry policy by failure category.
- Keep feed/list params fully encoded in key.
